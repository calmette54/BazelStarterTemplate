# Example: Python package with PyTorch, BUILD files by Gazelle

A small Python package: Pydantic models describe the inputs and results, a
mock "agent" summarizes a dataset with NumPy, and a PyTorch MLP is trained on
it (`ai_example/main.py` runs the whole workflow). The point of the example is
the Bazel setup: a hermetic Python 3.12, locked PyPI dependencies with
CPU-only PyTorch, and BUILD files that Gazelle writes from the imports.

## Run it

From this directory (the repository root ignores `examples/`):

```bash
bazelisk test //...                 # pytest suite + manifest check
bazelisk run //ai_example:main      # the full workflow
```

The first build downloads the PyTorch wheel (about 200 MB, 700 MB installed).

## How it is wired

| File | Role |
|---|---|
| `MODULE.bazel` | `rules_python` (Python 3.12), pip hub `pypi` with the PyTorch CPU index, Gazelle and its Python plugin |
| `requirements.in`, `requirements_lock.txt` | Direct dependencies, and the lock with hashes for all platforms |
| `gazelle_python.yaml` | Generated map from import names to wheels (e.g. `import functorch` → `@pypi//torch`), used by Gazelle |
| `BUILD.bazel` | `# gazelle:python_root`: imports are absolute from this directory (`from ai_example.models import ...`) |
| `ai_example/**/BUILD.bazel`, `tests/BUILD.bazel` | Generated by Gazelle: do not edit the deps by hand |

## Changing code or dependencies

- **After adding, moving or changing imports**, regenerate the BUILD files:
  `bazelisk run //:gazelle`. CI fails if they are out of date
  (`bazelisk run //:gazelle -- -mode=diff`).
- **After changing `requirements.in`**, relock and refresh the manifest:

  ```bash
  uv pip compile requirements.in --universal --python-version 3.12 --generate-hashes \
    --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple \
    --index-strategy unsafe-best-match -o requirements_lock.txt
  bazelisk run //:gazelle_python_manifest.update
  ```

  `//:gazelle_python_manifest.test` fails if you forget the second step.
- Tests are plain pytest files that end with
  `raise SystemExit(pytest.main([__file__]))`, so Bazel sees failures.
