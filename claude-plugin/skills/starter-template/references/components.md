# Concerns → template files

Paths are relative to the template checkout. "Project values" are what a
project changes; everything else is copied as is. `[x]` = marked block
`template:x` (see SKILL.md).

Contents: build · environment · format and lint · tests and coverage ·
release and stamping · CI · remote execution and GPU tests · container ·
documentation · repository hygiene · Claude Code

## 1. Hermetic build (always)

| File | Purpose |
| --- | --- |
| `.bazelversion`, `.bazeliskrc` | Bazel version; bazelisk runs the Aspect CLI (`bazelisk lint`) on top of it |
| `MODULE.bazel` | bzlmod deps; `[cpp]` fmt/doctest/googletest/hedron and rules_cuda (hermetic CUDA 12.8), the `remote_test_deps` pip hub (pytest for `test/remote`), `[benchmark]`, `[docs]` rules_doxygen, `[container]` rules_oci + base image + testcontainers pip hub |
| `bzl/toolchains.MODULE.bazel` | hermetic LLVM 19 + Debian bullseye sysroots (x86_64, aarch64), C++23; `include()`d by MODULE.bazel |
| `.bazelrc` | credential helper, `--config=aarch64/x86_64`, stamping, `[cpp]` CUDA flags, GPU test filters (`--config=gpu`, `--config=large-gpu`), `--config=remote` (section 7), `--config=ci`, coverage |
| `bzl/platforms/BUILD.bazel` | `linux-x86_64`, `linux-aarch64` platforms (used by the multi-arch image) |
| `tools/credential-helper`, `.bazelrc` `--credential_helper` lines | tweag credential helper for GitHub and Docker Hub downloads |
| `bzl/patches/` | `[cpp]` patch that makes hedron's compile-commands extractor load `py_binary`/`cc_binary` (Bazel 9 removed the native rules) |
| `.bazelignore` | nested modules (template: `examples`) |

Project values: `module(name, version)`; application deps.
Python: same files; `rules_python` toolchain 3.12 is already there; the
project's PyPI deps go in a second `pip.parse` hub `pypi` with
`//:requirements_lock.txt` (see `project-bootstrap/assets/python/MODULE.bazel.append`)
and `.bazelrc` gets the Python flags from `.../python/.bazelrc.append`.
Verify: `bazelisk build //...`, `bazelisk build //... --config=aarch64` (C++).
Details and pitfalls: `bazel-workspace` skill (`references/toolchains.md`).

## 3. Format and lint (always)

| File | Purpose |
| --- | --- |
| `bzl/format/BUILD.bazel`, root alias `//:format` | rules_lint `format_multirun`: clang-format (C/C++), ruff (Python) |
| `bzl/lint/linters.bzl`, `bzl/lint/BUILD.bazel` | aspects `clang_tidy`, `ruff` and their `lint_test` macros |
| `.aspect/cli/config.yaml` | aspects run by `bazelisk lint //...` |
| `.clang-format`, `.clang-tidy`, `.ruff.toml` | tool configs (root `BUILD.bazel` exports `.clang-tidy`, `.ruff.toml`) |
| `test/lint/BUILD.bazel` | `clang_tidy_test` `[cpp]`, `ruff_test`: **lint findings fail `bazelisk test //...`** |

Every new library/binary/test target is added to the `srcs` of the lint test
and gets `visibility = ["//test/lint:__pkg__"]` if it is not public.
Verify: `bazelisk run //:format` leaves no diff; `bazelisk test //test/lint/...`;
break a rule once to see the lint test fail.

## 4. Tests, benchmarks, coverage (always; benchmark optional)

| File | Purpose |
| --- | --- |
| `test/greeter/` | unit tests: doctest `[cpp]`; pytest for Python (overlay), `size = "small"` |
| `benchmark/` `[benchmark]` | google-benchmark as a `cc_test` |
| `.bazelrc` `coverage` lines | LLVM coverage, combined lcov in `bazel-out/_coverage/_coverage_report.dat` |
| `codecov.yaml` | Codecov settings (ignore `test/`) |

Rules: tests never skip on missing deps; pytest files end with
`raise SystemExit(pytest.main([__file__, "-q"]))`; make each new test fail once.
Python coverage needs `python.toolchain(configure_coverage_tool = True)`; the
template does not set it up yet.
Verify: `bazelisk test //...`, `bazelisk coverage //...`.

## 5. Release and stamping (always)

| File | Purpose |
| --- | --- |
| `.cz.yaml` | commitizen: conventional commits, `v$version` tags |
| `release-please-config.json`, `.release-please-manifest.json` | release-please, `release-type: bazel` (bumps `MODULE.bazel` version, writes CHANGELOG) |
| `tools/workspace_status.sh` | stamp keys: `STABLE_SEMANTIC_VERSION` (from the manifest), `STABLE_GIT_COMMIT[_SHORT]`, `STABLE_IMAGE_REGISTRY` |
| `BUILD.bazel` (root), `bzl/defs.bzl` | flags `--revision_mode` (`RELEASE`, `WIP`, `DIRTY`), `--release_version`, `--commit_sha` |
| `bzl/naming_convention.bzl`, `bzl/variables.bzl` | release tarball names `{product}_{target}_{mode}__v{version}.tar`; project name, description, repo URL, image name |
| `standalone/BUILD.bazel` `:tar` | release tarball (Python: `include_runfiles = True`, `[python]`) |
| `.github/workflows/release-please.yml` | release PR on `main`; on merge: tarballs for x86_64 + aarch64 attached to the release |

Project values: `bzl/variables.bzl`; manifest starts at `0.0.0` (first
release PR proposes `0.1.0`). `RELEASE_PLEASE_TOKEN` secret (PAT) so release
PRs trigger CI.
Verify: `bazelisk build //standalone:tar --revision_mode=RELEASE --release_version=1.2.3`
and check the file name; `./tools/workspace_status.sh`.

## 7. Remote execution and GPU tests (always; the CUDA test `[cpp]`)

A self-hosted NativeLink server runs every action under `--config=remote`
(laptop → ssh tunnel → server loopback). GPU tests ask for a GPU worker; the
server's `gpu-scaler` rents a vast.ai box for them and destroys it when idle.
Guide: `tools/remote/README.md`.

| File | Purpose |
| --- | --- |
| `bzl/gpu.bzl` | `GPU` / `LARGE_GPU`: tags `requires-gpu` / `requires-large-gpu` and `exec_properties = {"test.gpu": "cuda"}` |
| `tools/remote/BUILD.bazel` | execution platform `:platform` (`gpu: none`) of `--config=remote`; exports for the test |
| `tools/remote/server/` | `setup.sh` (installs NativeLink, vastai, systemd units), `nativelink.json5` (CAS, scheduler with `gpu: exact`, CPU worker), `gpu-scaler` + `gpu.env` (rent, tunnel, drain, destroy, spend cap) |
| `tools/remote/worker/nativelink.json5` | the GPU box's worker (`gpu: cuda`, CAS and scheduler through reverse ssh tunnels) |
| `.bazelrc` `remote`, `gpu`, `large-gpu` | remote executor `grpc://127.0.0.1:50051`, minimal downloads, test timeouts; tag filters |
| `test/remote/` | `gpu_scaler_test`: the scaler against fake vastai/ssh/scp/curl (CPU) |
| `test/cuda/` `[cpp]` | `saxpy_test`: a CUDA kernel, the smallest GPU test |

Every test that needs a GPU uses `exec_properties = GPU.exec_properties,
tags = GPU.tags` (or `LARGE_GPU`). The CUDA archs in `.bazelrc` and the GPU
list in `gpu.env` go together.
Project values: the server host (`rbe-server` in `~/.ssh/config`), `gpu.env`
(GPUs, prices, spend cap), `VAST_API_KEY` at setup.
Verify: `bazelisk test //test/remote/...`; with a GPU,
`bazelisk test --config=gpu //test/cuda:saxpy_test`; end to end,
`bazelisk test --config=remote --config=gpu //...` and `gpu-scaler status` on the server.

## 8. Container image (optional: `container`)

| File | Purpose |
| --- | --- |
| `MODULE.bazel` `[container]` | rules_oci, `oci.pull` of ubuntu by digest for amd64 + arm64 |
| `standalone/BUILD.bazel` `[container]` | `oci_image`, `multi_arch` (transition in `bzl/transition.bzl`), `oci_image_index`, stamped labels and tags, `oci_push` `:push_image`, `oci_load` `:load_image` and `:load_host_image` |
| `integration/` | Python testcontainers test that runs the image (tags `requires-docker`, `local`) |
| `release-please.yml` `[container]` | push to `ghcr.io/<owner>/<IMAGE_NAME>` on release |

Tags: RELEASE → `vX.Y.Z`; WIP → short sha; DIRTY → short sha + `latest`.
Python images run the binary's runfiles (hermetic interpreter) with the
`bootstrap_impl=script` launcher; no Python in the base image.
Verify: `bazelisk run //standalone:load_image`, then
`DOCKER_HOST=... TESTCONTAINERS_RYUK_DISABLED=true bazelisk test //integration:standalone_image_test`
(rootless Podman: `podman system service --time=0 unix://$XDG_RUNTIME_DIR/podman/podman.sock`).

## 10. Repository hygiene (always)

`.gitignore` (anchored `/bazel-*`, devenv, direnv, compile_commands),
